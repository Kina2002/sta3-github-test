# 공고별 지원 준비 묶음

## 대상

- 회사: `collection://b90d0c57-448b-411b-a5cc-5431e9be756b`
- 공고: `collection://10c1ca20-463c-4e30-9fb5-2bfb7672e541`
- 지원 기록: `collection://5063a06c-0258-4bfa-a6a0-959eeb9ce31a`
- 첫 화면: https://app.notion.com/p/3dcf2f0727e88139858ccf677b21798b

기존 회사·공고·지원 기록을 먼저 가져와 같은 지원 기록이 있는지 확인한다. 있으면 새 페이지를 중복 생성하지 않고 그 페이지를 확장한다.

## 출처와 사실 확인

- 공고의 담당 업무, 자격요건, 고용형태, 근무지, 제출 방식과 마감일시는 원문에서 다시 확인한다.
- 회사의 제품, 사업, 품질체계와 연구 방향은 공식 홈페이지를 우선한다.
- 회사가 스스로 소개한 내용, 채용 플랫폼 정보와 Codex의 해석을 구분한다.
- 공고에 없는 분석기기, 급여, 교육체계나 업무를 있다고 단정하지 않는다. 확인이 필요하면 면접 질문으로 바꾼다.

## 지원자 경험 사용 원칙

- 작업일지와 대화에서 사용자가 실제로 말한 경험만 쓴다.
- 사용자가 직접 담당한 범위, 결과 수치와 사용 장비가 확인되지 않으면 만들지 않는다.
- 초안에는 확인이 필요한 사실을 분명히 표시하고, 사용자가 채운 뒤 최종 문장으로 다듬는다.

## 묶음 구성

지원 기록 페이지에 다음을 공고에 맞게 작성한다.

1. 회사와 업종 한눈에
2. 공고 핵심 조건
3. 지원할 가치와 확인할 조건
4. 공고 요구와 사용자 경험 연결표
5. 자기소개서 핵심 뼈대
6. 예상 면접 질문과 답변 방향
7. 제출 전 확인 목록
8. 지금 할 일
9. 확인에 사용한 출처

자기소개서 뼈대는 상황, 본인의 행동, 확인된 결과, 지원 직무 연결 순서로 만든다. 면접 질문은 공고 업무와 경험의 빈틈을 확인할 수 있게 고른다.

## Notion 반영

- 지원 기록의 `회사 공부 요약`, `예상 면접 질문`, `다음 할 일`, `배운 점`을 현재 묶음과 맞춘다.
- 지원 기록, 회사와 채용공고의 관계는 유지한다.
- 첫 화면의 `더 자세히 보기`에는 현재 가장 먼저 준비할 공고의 묶음 하나만 `🧰` 아이콘과 함께 연결한다. 새 묶음을 만들 때 링크를 끝없이 추가하지 않고 현재 최우선 대상을 바꾼다.
- 공고 제출, 개인정보 전송이나 지원 버튼 클릭은 사용자가 직접 확인하고 결정한다.

작성 뒤 페이지를 다시 가져와 모든 구역, 출처, 관계와 첫 화면 링크를 확인하고 `작업일지.md`에 남긴다.
