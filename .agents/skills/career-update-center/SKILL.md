## 명령별 실행

### 지원서 업데이트

1. 공고에서 `지원서 제출항목`, `자기소개서 질문`, `문항 조건`을 읽는다.
2. 특정 공고를 말하지 않았다면 `지원서 업데이트 필요`가 선택되어 있거나 자기소개서 질문이 입력된 공고만 대상으로 삼는다.
3. 내 지원 소재의 `상황`, `내 행동`, `결과·근거`, `사용 장비·도구`, `핵심 역량`, `직무 연결`, `산업 연결`을 읽는다.
4. 질문별로 소재를 고르고 적합한 이유, 사용할 사실, 보완할 사실을 구분한다.
5. 연결된 지원 기록을 찾아 아래 전체 묶음을 작성한다. 같은 기록이 있으면 중복 생성하지 않고 갱신한다.
6. 지원 기록의 `추천 소재`, `문항별 추천 소재`, `소재 매칭 상태`, `회사 공부 요약`, `예상 면접 질문`, `다음 할 일`을 함께 맞춘다.
7. 공고의 `지원서 업데이트 필요`를 해제하는 것은 묶음 작성과 검증이 모두 끝난 뒤에만 한다.

지원 준비 묶음에는 반드시 다음 구역을 모두 넣는다.

1. 회사 업종
2. 공고 핵심
3. 왜 지원할 가치가 있나
4. 지원 전 확인할 것
5. 내 경험 연결표
6. 자기소개서 핵심
7. 예상 면접 질문과 답변 방향
8. 제출 전 확인 목록

`내 경험 연결표`에는 공고 요구, 추천 소재, 연결 근거, 보완할 사실을 표시한다. `자기소개서 핵심`은 문항별로 상황, 본인 행동, 확인된 결과, 직무 연결 순서의 뼈대를 만든다. 완성 문장을 요청받아도 확인되지 않은 사실은 빈칸 또는 `확인 필요`로 둔다.

### 내 소재 업데이트

- 사용자가 새로 쓴 행을 읽고 경험 유형, 역량, 직무, 산업 연결을 정리한다.
- 상황·행동·결과가 섞여 있으면 각각의 속성으로 나눈다.
- 수치, 사용 장비, 직접 담당 범위가 불분명하면 묻거나 `확인 필요`로 표시한다.
- 같은 사건을 표현만 바꿔 중복 생성하지 않는다.

### 공고 업데이트

- `job-tracker-refresh` 절차로 신규·변경·마감 공고를 갱신한다.
- 이어서 `job-priority-dashboard` 절차로 이번 주와 전체 추천순을 갱신한다.
- 사용자가 적은 지원서 제출항목과 자기소개서 질문은 보존한다.

### 뉴스 업데이트

- `industry-newsletter-refresh` 절차로 최신 호를 발행하고 검증 뒤 Slack `#산업뉴스레터`에 공유한다.

### 전체 업데이트

1. 공고 업데이트
2. 지원 우선순위 갱신
3. 내 소재 정리
4. 지원서 업데이트
5. 뉴스 업데이트와 Slack 공유

앞 단계가 실패하면 무엇까지 끝났는지 남기고, 실패한 이후 단계에서 중복 생성이 생기지 않도록 기존 결과를 다시 확인한다.

## 사실과 안전 원칙

- 회사·공고 정보는 공식 채용 페이지와 회사 공식 자료를 우선한다.
- 사용자 경험은 내 지원 소재 보관함과 사용자가 직접 확인한 대화 내용만 사용한다.
- 성과 수치, 기기 운용 범위, 역할, 자격을 추측하지 않는다.
- 지원서 제출, 개인정보 전송, 외부 지원 버튼 클릭은 자동으로 하지 않는다.
- 갱신 뒤 대상 페이지와 관계 속성을 다시 가져와 검증하고 `작업일지.md`에 남긴다.
